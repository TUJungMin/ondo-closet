# 온도옷장 — Claude Code 작업 지침

이 파일은 저장소 루트에 둔다. Claude Code는 작업을 시작할 때 이 파일을 먼저 읽는다.

## 1. 프로젝트 한 줄 요약

내 옷장 사진을 등록하면 AI가 종류·색상을 분석하고, 날씨·장소·옷 상태·체감 온도 기록을 반영해 오늘 입을 코디를 추천하는 웹 서비스.

- 대회: 2026 대한민국 청년 CAREER FAIR AI 해커톤 (대한상공회의소)
- 제출 마감: **2026-11-23(월) 17:00**, 내부 목표 15:00
- 일정: 금요일까지 기능 연결 → 토요일 검증 → 일요일 제출본 완성
- 마감 이후에는 기능·프롬프트·데이터를 바꿀 수 없다. 제출본이 곧 본선(12/7) 시연본이다.

## 3. 작업 원칙 (반드시 지킬 것)

1. **첫 작업은 현재 구현 상태 확인이다.** 기존 프로토타입이 있으므로 저장소 구조, 기술 스택, 실제 브라우저 동작 여부를 먼저 보고한다. 스택을 임의로 바꾸지 않는다.
2. **핵심 흐름 하나가 끝까지 작동하는 것이 최우선이다.** 필수 기능이 전부 연결되기 전에는 추가 기능에 손대지 않는다.
3. **실제 개인정보를 쓰지 않는다.** 얼굴·전신이 나온 사진, 실명, 연락처를 코드·시드 데이터·화면에 넣지 않는다. 사진은 외부 AI API로 보내지 않고 서버 안에서 분석한다.
4. **외부 자원은 쓸 때마다 기록한다.** 오픈소스, 모델, 데이터, API를 추가하면 `ai/docs/external-resources.md`에 명칭·출처 링크·라이선스·사용 위치를 한 줄씩 적는다. 대회 제출 별첨에 그대로 옮긴다.
5. **이용 권한이 불분명한 이미지·데이터는 저장소에 넣지 않는다.** (7장 참고)
6. 확정되지 않은 사항은 추측으로 채우지 말고 질문한다. (9장 참고)

## 4. 화면 방향

**방향: 디지털 옷장 앱을 웹으로 옮긴 느낌.** Acloset 같은 디지털 옷장 앱이 주는 사용감(휴대폰에서 한 손으로 쓰는 옷장)을 참고하되, 화면·로고·아이콘·문구·색상은 우리 것으로 새로 만든다. 특정 앱의 화면을 그대로 따라 그리지 않는다.

- **모바일 우선 웹.** 기준 폭 390px, 데스크톱에서는 가운데 정렬된 휴대폰 폭 레이아웃으로 보인다.
- **하단 탭 4개:** 옷장 / 오늘 추천 / 기록 / 내 설정
- **옷장 화면:** 배경을 지운 옷 이미지가 격자로 놓인다. 위쪽에 종류 필터(전체·상의·바지·스커트·겉옷·신발)와 상태 필터(입을 수 있음·세탁·건조·수선).
- **옷 등록:** 사진 선택 → AI가 제안한 종류·색상을 보여줌 → 사용자가 고치고 저장. AI 제안에는 "AI 제안"임을 표시하고 언제든 수정할 수 있게 한다.
- **오늘 추천:** 위쪽에 오늘 날씨와 장소 선택. 고정한 옷 한 벌이 강조되고, 나머지 옷이 그 주위에 조합된다. 추천마다 "왜 이 조합인지" 한 줄 이유를 보여준다.
- **거절과 피드백:** 추천 카드에서 거절하면 이유를 고른다(너무 얇음, 색이 안 맞음, 장소에 안 맞음, 직접 입력). 착용 후에는 추웠어요·적당했어요·더웠어요 세 버튼.
- **기록:** 날짜별로 입은 코디와 체감 기록을 본다.
- **분위기:** 옷 사진이 주인공이 되도록 배경은 차분하게. "온도"라는 이름에 맞게 추움~더움을 나타내는 색 단계를 체감 기록과 날씨 표시에 일관되게 쓴다.

**우리만의 차별점이 화면에서 바로 보여야 한다:** 한 벌 고정, 옷 상태 제외, 체감 온도 기록, 거절 이유 반영. 이 네 가지가 기존 옷장 앱과 다른 점이므로 숨기지 말고 주요 화면에 드러낸다.

## 5. 핵심 흐름과 기능 우선순위

```
옷 사진 등록 → AI가 종류·색상 제안 → 사용자 확인·수정 후 저장
→ 오늘 입고 싶은 옷 한 벌 고정
→ 날씨·장소·착용 가능 상태를 반영해 코디 추천
→ 착용 후 체감과 만족도 기록 → 다음 추천에 반영
```

**필수 (이 순서로 구현)**
1. 옷 사진 등록과 저장
2. AI 기반 종류·색상 분석, 결과 직접 수정
3. 한 벌 고정 코디 추천
4. 세탁·건조·수선 중인 옷 제외
5. 날씨·장소에 따른 겉옷·신발 추천
6. 추천 거절 이유 저장과 순위 조정
7. 추웠어요·적당했어요·더웠어요 기록 반영

**추가 (필수 완료 후에만)**
- 자주 입는 옷 10벌로 시작하는 모드
- 안 입는 옷의 이유 기록과 활용 추천
- 참고 이미지와 보유 의류 조합 함께 표시

**만들지 않는다 (후속 개발)**
- Pinterest 계정 연동, 3D 마네킹·가상 착용, 신체 치수 기반 핏 예측

## 6. 데이터와 AI

**옷 데이터 항목**

| 항목 | 설명 |
|---|---|
| id | 고유 ID |
| photo | 원본 사진, 배경 제거 이미지 |
| name | 이름 |
| category | 상의·바지·스커트·겉옷·신발 |
| colors | 대표색 최대 2개 |
| warmth | 보온성 단계 |
| style | 스타일 |
| status | 입을 수 있음·세탁·건조·수선 |
| favorite | 즐겨찾기 |
| waterproof, grip | 방수·접지 여부 (주로 신발·겉옷) |

**이미지 분석 (기본안, 평가 후 확정)**

| 역할 | 모델 | 라이선스 |
|---|---|---|
| 종류 분류 | `Marqo/marqo-fashionSigLIP` (제로샷) | Apache-2.0 |
| 배경 제거 | `ZhengPeng7/BiRefNet` | MIT |
| 색상 | 배경 제거 후 옷 픽셀에서 대표색 계산 (모델 아님) | — |
| 비교 기준선 | `patrickjohncyh/fashion-clip` | MIT |
| 여러 옷 사진 (선택) | `valentinafeve/yolos-fashionpedia` | MIT |

**종류 분류: `Marqo/marqo-fashionSigLIP`**
- 사진과 후보 문구를 함께 넣으면 문구별 확률이 나오는 제로샷 방식이다. 추가 학습 없이 쓴다.
- 후보 문구는 영어로 준다(예: "a top", "pants", "a skirt", "outerwear", "shoes"). 결과는 한글 종류명으로 바꿔 저장한다.
- 같은 방식으로 보온성(두꺼운 겨울 옷 / 얇은 여름 옷)과 스타일 초안도 뽑는다.
- 정확도가 낮으면 추가 학습보다 후보 문구 조정을 먼저 한다.
- `AutoModel`, `AutoProcessor`로 불러오며 `trust_remote_code=True`가 필요하다.

**색상: `ZhengPeng7/BiRefNet`으로 배경 제거 → 대표색 계산**
- 색상은 모델에게 묻지 않는다. 배경을 지우고 남은 옷 픽셀을 k-means로 묶어 대표색 상위 2개를 뽑고, 미리 정한 색 이름표(검정·흰색·회색·베이지·갈색·남색 등)에서 가장 가까운 이름으로 바꾼다.
- 배경 제거 이미지는 옷장 화면 표시용으로도 저장한다.
- BiRefNet 예제 코드는 GPU와 1024×1024 입력을 전제로 한다. CPU에서 사진당 처리 시간을 먼저 재고, 너무 느리면 더 가벼운 배경 제거 도구(rembg 등)로 바꾼다.

**공통**
- 모델은 서버 안에서 직접 실행한다. 외부 추론 API에 의존하지 않는다.
- 분석 실패나 낮은 확신도일 때는 값을 비워 두고 사용자에게 직접 고르게 한다. 틀린 값을 확정처럼 보여주지 않는다.
- 추천 로직은 규칙과 점수 기반으로 시작한다. 추천 결과마다 근거(날씨, 고정 옷, 과거 체감 기록)를 함께 반환한다.
- 추가 학습은 평가에서 문제가 확인된 경우에만 검토한다.

**평가 기록 (`ai/docs/eval.md`)**
- 종류 분류 정확도, 색상 일치 여부, 사진당 처리 시간
- 복잡한 배경, 어두운 사진, 여러 옷이 있는 사진을 따로 구분해 기록
- 평가용 사진은 학습·문구 조정에 쓴 사진과 분리해 둔다

## 7. 테스트 데이터 기준

- **Pinterest 이미지는 내려받거나 저장소·서버에 넣지 않는다.** Pinterest 약관은 사전 허가 없는 자동 수집을 금지하고, 이미지 저작권은 각 원작자에게 있다. 대회 규칙상 무단 수집 데이터는 심사 제외·수상 취소 사유다.
- Pinterest 검색 결과는 사람이 눈으로 보고 "가을 코디에 어떤 조합이 나오는지" 참고하는 용도로만 쓴다.
- **실제로 쓰는 데이터**
  1. 팀원이 직접 찍은 옷 단품 사진 (얼굴·신체 제외) — 주 데이터
  2. 이용 조건을 확인한 무료 이미지 — 출처와 라이선스를 `ai/docs/external-resources.md`에 기록
- 시드 데이터는 가을 옷 위주로 30벌 안팎을 준비해 가을 코디 시연이 되게 한다.
- 스크래퍼, 크롤러, 자동 다운로드 스크립트를 만들지 않는다.

## 8. 제출물 체크

- 프로토타입 링크: 심사위원이 로그인 없이(또는 시연 계정으로) 바로 접속·실행 가능해야 한다
- 프로젝트 소개서 PDF 본문 10장 이내 + 별첨(팀 구성, 사전 개발 내역, 외부 자원 출처)
- AI 활용내역: 사용 모델, API, 외부 데이터, 생성형 AI 활용 범위 (Claude Code·Codex 사용 포함)
- 선택: 시연 영상 3분 이내, 소스코드 저장소 링크
- 사전 개발 내역 고지를 위해 **해커톤 이전에 만든 범위와 기간 중 만든 범위를 커밋으로 구분**할 수 있게 한다

## 9. 아직 정해지지 않은 것 (작업 전 확인)

- 기존 프로토타입의 기술 스택과 실제 동작 범위
- AI 실행 위치: 백엔드 서버 내 직접 실행인지, 별도 추론 서버인지 (서준호·곽정민이 결정)
- 배포 환경과 GPU 유무
- 날씨 정보 출처 (공공 API 사용 여부와 이용 조건)
- 서비스 이름 표기, 로고, 대표 색상
