# 평가 기록

이미지 분석의 종류 분류 정확도, 색상 일치, 사진당 처리 시간을 적는다. (CLAUDE.md 6장)

마지막 갱신: 2026-11-22

## 현재 상태

- **정식 평가는 아직 하지 않았다.** 팀이 직접 찍은 평가용 사진이 아직 없다. 아래 2장의 숫자는 모델이 실제 사진에서 도는지 본 **동작 확인(6장)** 이고, 정확도로 인용할 수 없다.
- 처리 시간(1장)은 개발 PC에서 실제로 잰 값이다. 배포 서버가 정해지면 그 서버에서 다시 잰다.
- 옷이 여러 벌 찍힌 사진을 옷별로 나누는 기능은 착용 사진 1장으로만 확인했다(2-1장).
- 정식 평가 방법과 채울 표는 4장에 있다. 착용 사진 평가도 `evaluate.py`에 넣었다(2026-11-22).
- 추천 한 번에 걸리는 시간(3장)과 서버 시작 워밍업의 효과(1장)는 2026-11-22에 쟀다.
- 백엔드(`jungmin` 브랜치)와 두 서버를 띄워 분석·추천 응답 형식이 맞물리는 것을 확인했다(2026-11-22). 이때 쓴 사진은 그림으로 만든 시험용 2장이라 정확도와는 무관하다.

## 1. 사진당 처리 시간

측정: 2026-11-18, `ai/scripts/benchmark.py`, 사진 6장(긴 변 1280px), 모델 로드와 첫 추론을 뺀 뒤의 시간.

| 장치 | 배경 제거 입력 | 배경 제거 | 색상 | 분류 | 전체(사진당) |
|---|---|---:|---:|---:|---:|
| GPU — RTX 5060 Ti 16GB, half precision | 1024×1024 | 202 ms | 45 ms | 14 ms | **297 ms** |
| CPU — Core Ultra 9 285 (24스레드) | 1024×1024 | 9,958 ms | 60 ms | 52 ms | **10,111 ms** |
| CPU — 같은 PC | 512×512 | 2,312 ms | 49 ms | 52 ms | **2,468 ms** |

옷이 여러 벌 찍힌 사진(착용 사진 1장, 옷 3벌 검출) — 옷 찾기와 옷별 분석이 추가되고, 배경 제거는 사진 전체에 한 번만 한다.

| 장치 | 배경 제거 입력 | 옷 찾기 | 배경 제거 | 옷별 분석(3벌) | 전체(사진당) |
|---|---|---:|---:|---:|---:|
| GPU — RTX 5060 Ti 16GB | 1024×1024 | 67 ms | 194 ms | 197 ms | **489 ms** |
| CPU — Core Ultra 9 285 | 1024×1024 | 142 ms | 9,775 ms | 349 ms | **10,294 ms** |
| CPU — 같은 PC | 512×512 | 140 ms | 2,228 ms | 365 ms | **2,761 ms** |

- 모델 로드: GPU 약 7초, CPU 약 9~16초(빈 사진 한 번 추론 포함). 서버 시작 때 `warmup()`을 불러 두면 첫 사용자 요청도 위 시간대로 나온다. 불러 두지 않으면 GPU 첫 추론에만 약 16초가 걸렸다.
- 서버 시작 때 자동 워밍업(`ONDO_WARMUP=outfit`, 2026-11-22 추가): 두 번째 개발 PC(RTX 3060 12GB, Ryzen 7 5800X)에서 가중치가 이미 내려받아진 상태로 쟀다. 그림으로 만든 시험용 사진 1장씩이라 정확도와는 무관하다.

  | 띄우는 방법 | `/ai/health` | 첫 한 벌 분석 | 첫 여러 옷 분석 |
  |---|---|---:|---:|
  | 워밍업 없음 (기본) | 시작 1초 뒤부터 `ok` | 13.1초 | 0.8초 |
  | `ONDO_WARMUP=outfit` | 시작 1초 뒤 `loading` → 약 15초 뒤 `ok` | 0.35초 | 0.10초 (옷을 찾지 못한 그림) |

  가중치를 처음 내려받는 PC에서는 워밍업 없이 보낸 첫 분석 요청이 191초 걸렸다(내려받기 포함). 백엔드의 응답 대기 시간 120초를 넘으므로, 배포 서버에서는 워밍업을 켜고 `ok`가 된 뒤에 시연한다.
- GPU 메모리: BiRefNet half precision 1024 입력에서 최대 약 1.6GB.
- 시간의 대부분은 배경 제거다. 분류(FashionSigLIP)는 어느 장치에서도 병목이 아니다.

### 배경 제거 입력 512 대 1024

`ONDO_SEGMENT_SIZE=512`로 바꾸면 코드 변경 없이 입력 크기가 줄어든다. 같은 6장에서 비교했다.

| 사진 | 옷 영역 겹침 (IoU) | 대표색 |
|---|---:|---|
| 모피 코트 | 0.996 | 같음 |
| 갈색 바지 | 0.990 | 같음 |
| 주름 스커트 | 0.998 | 같음 |
| 스니커즈 | 0.996 | 같음 |
| 트렌치코트 | 0.997 | 같음 |

배경이 단순한 사진에서는 512로도 결과가 사실상 같았다. 복잡한 배경, 레이스·니트 올처럼 가는 가장자리에서의 차이는 확인하지 못했다.

### 배포 장치에 따른 판단

- **GPU 서버**: BiRefNet 1024 그대로. 사진당 약 0.3초.
- **CPU 서버**: 고성능 데스크톱 CPU에서도 1024 입력은 사진당 약 10초라 등록 화면에서 기다리기 길다. 512로 시작한다(이 PC에서 약 2.5초). 클라우드의 2~4코어 CPU에서는 이보다 몇 배 느릴 것으로 보이지만 재 보지 않았다. 배포 서버에서 `benchmark.py`로 다시 재고, 그래도 느리면 CLAUDE.md 6장대로 rembg 같은 가벼운 도구로 바꾼다. 바꿀 곳은 `ai/ondo_ai/vision/background.py`의 `BiRefNetRemover` 하나다.

### 여기서 확인된 것

| 관찰 | 조치 |
|---|---|
| 아이보리를 베이지로 부른 경우 2건. 이웃한 색 사이의 혼동이다 | 팀 사진으로 평가한 뒤 `palette.py` 견본을 조정한다. 6장만 보고 맞추면 과적합이라 지금은 두었다 |
| 밝은 아이보리 실크를 처음에는 회색으로 불렀다 | 수정함: 밝은 색은 옅은 색조도 무채색으로 보지 않게 하고, 견본과의 거리에서 밝기 비중을 절반으로 낮춤 |
| 그늘진 베이지 코트를 처음에는 카멜로 불렀다 | 위와 같은 수정으로 해결 |
| 투명 배경 PNG를 열 때 투명한 곳이 검정으로 읽혀, 티셔츠 선화의 색이 검정으로 나왔다 | 수정함: 투명 PNG는 흰 바탕에 올려서 읽는다 |
| 그 선화는 흰 바탕에 선만 있어 배경 제거가 윤곽선만 잡는다 | 수정함: 옷 둘레 상자 안이 거의 비어 있으면 배경 제거 실패로 보고, 색을 비우고 경고를 낸다. 흰 바탕에 놓인 흰 옷 실물 사진에서 어떤지는 아직 확인하지 못했다 |
| 처리 시간을 잴 때 CPU에서 배경 제거가 33ms로 찍혔다. 실제로는 실패하고 있었다 | 수정함(아래 half precision 항목). `benchmark.py`가 경고를 함께 출력하게 바꿈. 단계가 실패하면 시간이 짧게 찍히므로 시간만 보지 않는다 |
| 어두운 갈색 후드티를 검정으로 불렀다 (착용 사진 1장, 저장소 미포함). 옷의 절반 가까이가 그늘이라 평균 색이 거의 검정이었다 | 수정함: 대표색을 묶음 평균이 아니라 빛을 받은 쪽으로 절반 당겨 잡는다. 단, 밝은 쪽에도 색조가 없는 어두운 옷은 당기지 않는다(검정 옷의 광택을 회색으로 읽지 않게). 같은 사진의 아주 어두운 카키 바지는 여전히 검정으로 나온다(경계선상의 색) |
| 아이보리와 검정 두 색 옷이 '회색' 하나로 뭉치는 경우가 있었다. 중간 밝기 묶음이 다리가 되어 두 색을 이어 붙였다 | 수정함: 색 묶음을 합칠 때 합쳐진 평균이 아니라 가장 큰 묶음(기준 색)과 직접 비교한다 |
| 한 장에 옷이 여러 벌인 착용 사진을 한 벌 분석에 넣으면 사람 전체가 한 덩어리로 잡힌다. 종류는 비워 두고 경고를 내지만 색은 섞인 값이 나온다 | 여러 옷 분석 경로를 추가함(`analyze_outfit`, 2-1장). 한 벌 분석에 넣었을 때의 동작은 그대로다 |
| 옷걸이·스탠드가 옷과 함께 남는다 | 대표색에는 영향이 없었다(갈색 95%). 옷장 화면에서 보기에 거슬리는지는 팀 사진으로 확인 필요 |
| 스타일 제안은 초안 수준이다 (모피 코트 → 스트릿) | 사용자 수정 전제. 평가 후 문구 조정 |
| `AutoModel`로는 FashionSigLIP이 로드되지 않는다 (transformers 5.23.0, `Cannot copy out of meta tensor`) | 모델 카드의 다른 공식 경로인 OpenCLIP으로 로드. 같은 가중치 |
| BiRefNet 가중치가 half precision으로 저장돼 있어 CPU에서 그대로는 추론이 실패한다 | 수정함: CPU에서는 float32로 바꿔 올린다 |

## 2-1. 여러 옷 사진 동작 확인 (1장, 정확도 평가 아님)

`valentinafevu/yolos-fashionpedia`로 옷 위치를 찾고, 옷마다 한 벌 분석과 같은 과정을 돌린다.
사진: 팀원이 제공한 착용 사진 1장(후드티 + 와이드 팬츠 + 스니커즈 + 가방, 얼굴 없음). 출처를 확인하지 못해 저장소에 넣지 않았다.
이 사진을 보면서 규칙을 정했으므로 아래는 "이 사진에서 의도대로 동작한다"는 확인일 뿐이다.

| 눈으로 본 정답 | 검출 (점수) | 분석 결과 | 판정 |
|---|---|---|---|
| 갈색 후드티 | jacket (0.73) | 상의 · 후드티 · 갈색 · 보온 4 → "갈색 후드티" | 맞음. 검출 모델은 jacket이라 했지만 분류 모델이 상의로 고침 |
| 아주 어두운 카키 와이드 팬츠 | pants (0.97) | 바지 · 코듀로이 팬츠 · 검정 · 보온 4 → "검정 코듀로이 팬츠" | 종류 맞음. 색은 검정으로 나옴(경계선상), 소재는 확인 불가 |
| 흰색 스니커즈 | shoe (0.97, 0.91) | 신발 · 스니커즈 · 아이보리 → "아이보리 스니커즈" | 맞음(흰색 대신 아이보리). 두 짝을 한 벌로 묶음 |
| 후드티 안의 체크 셔츠 | 못 찾음 | — | 놓침. 깃과 밑단만 보여 검출되지 않음 |
| 가방 | bag (0.71) | 옷장 종류가 아니라 `skipped`에 "가방" | 의도대로 |

CPU에서도, 배경 제거 입력을 512로 줄여도 같은 결과가 나왔다.

단품 사진 6장을 이 경로에 넣어 본 결과: 코트·바지·스커트·트렌치코트는 한 벌로 찾았고 색도 한 벌 분석과 같았다. 티셔츠 선화도 한 벌로 찾았고 색은 비웠다. **단품 신발 사진은 찾지 못했다**(경고와 함께 빈 결과). 검출 모델이 사람이 입은 사진으로 학습됐기 때문으로 보인다. 단품 사진은 한 벌 분석을 쓴다.

### 넣은 규칙과 그 한계

| 규칙 | 이유 | 한계 |
|---|---|---|
| 검출 점수 0.5 이상, 사진 넓이의 3% 이상(신발은 0.2%)만 옷으로 본다 | 소매·주머니 같은 부분과 작은 오검출 제거. 스커트 허리 부분이 '상의'(0.63)로 잡힌 사례가 있었다 | 멀리서 찍어 옷이 작게 나온 사진은 놓칠 수 있다 |
| 상체는 상의·겉옷 가운데 분류 모델이 고르고, 하체·신발은 검출 모델의 종류를 따른다 | 후드티가 jacket으로 검출됐다. 신발 영역은 바짓단 때문에 그냥 분류하면 바지로 나왔다 | 와이드 팬츠와 긴 스커트의 구분은 검출 모델에 달려 있다 |
| 같은 부위에서 다른 상자 안에 든 옷은, 종류나 대표색이 같으면 같은 옷으로 보고 뺀다 | 후드티 한 벌이 큰 상자(jacket)와 가슴 부분의 작은 상자(top)로 두 번 잡혔다 | 같은 색 옷을 겹쳐 입으면 안쪽 옷을 놓친다 |
| 다른 부위 옷과 30% 이상 겹치는 옷에서는 그 옷의 대표색을 뺀다 | 바짓단이 신발 위를 덮어 신발 색이 "검정, 아이보리"로 나왔다 | 검정 바지에 검정·흰색 신발이면 신발의 검정도 빠진다 |
| 배경 제거는 사진 전체에 한 번만 하고 옷마다 자기 상자 안쪽만 쓴다 | 옷 수만큼 반복하지 않아 CPU에서도 시간이 늘지 않는다 | 상자 안에 든 손·휴대폰·가방끈이 배경 제거 이미지에 함께 남는다 |

확인하지 못한 것: 겉옷을 열어 입고 안에 다른 색 옷이 보이는 사진, 스커트 착용 사진, 여러 벌을 바닥에 펼쳐 놓은 사진, 사람이 둘 이상인 사진, 원피스. 얼굴이 나온 사진인지는 확인하지 않는다.

## 3. 추천 엔진 확인

추천은 모델이 아니라 규칙이라 정확도 대신 동작을 테스트로 고정했다. `ai/tests/test_recommend.py` (예시 옷장 30벌):

- 한 벌 고정: 고정한 옷이 모든 추천에 들어간다 (상의·하의·겉옷·신발 어느 것을 고정해도)
- 옷 상태: 세탁·건조·수선 중인 옷은 추천에 나오지 않고, 제외 목록과 근거에 표시된다
- 날씨: 추울수록 보온 지수가 높은 조합, 28°C에는 겉옷 없음, 4°C에는 겉옷 포함, 비 오면 방수 신발, 눈 오면 접지 신발
- 체감 기록: '추웠어요'가 쌓이면 기준 온도가 내려가 더 따뜻한 조합이 나오고, 오래된 기록일수록 덜 반영된다
- 거절 이유: 네 가지 이유 모두 거절한 조합이 1순위에서 내려가고, '색이 안 맞음'은 그 색 조합을, '장소에 안 맞음'은 그 장소에서 해당 옷을 뒤로 보낸다

기온별 두께 기준, 색 조합 규칙, 장소별 스타일 적합도는 팀이 직접 정한 값이라 시연 데이터로 추천을 뽑아 보고 어색한 곳을 조정해야 한다.

### 추천 한 번에 걸리는 시간

측정: 2026-11-22, `ai/scripts/bench_recommend.py --url http://127.0.0.1:8000`, 개발 PC(Ryzen 7 5800X, Python 3.11), 20번 반복의 중앙값(괄호는 최댓값). 추천은 모델을 쓰지 않아 GPU와 무관하다.

백엔드는 고정 옷이 없으면 상의 최대 5벌을 차례로 고정해 `/ai/recommend`를 5번 부른다. 요청에는 백엔드가 실제로 보내는 필드만 넣었다(`status`·기록 없음 → 모든 옷이 조합 대상인 가장 느린 경우). 12벌은 게스트 옷장과 같은 구성(상의 4·바지 3·겉옷 3·신발 2), 50벌은 상의 16·바지 9·스커트 3·겉옷 12·신발 10이다.

| 옷장 | 고정 옷 | top_k | 점수 매기는 조합 수 | 엔진만 | HTTP 왕복 (한 번 기준) |
|---|---|---:|---:|---:|---:|
| 12벌 | 상의 1벌 | 3 | 24 | 1.2 ms (1.5) | 2.7 ms (3.3) |
| 12벌 | 신발 1벌 | 3 | 48 | 2.4 ms (2.7) | 4.3 ms (4.9) |
| 12벌 | 신발 1벌 | 10 | 48 | 5.6 ms (6.4) | 7.1 ms (8.3) |
| 12벌 | 상의 5벌 연속 (5번 합계) | 3 | 96 | 4.7 ms (4.9) | 10.7 ms (20.4) |
| 50벌 | 상의 1벌 | 3 | 1,560 | 64.0 ms (71.2) | 65.8 ms (71.4) |
| 50벌 | 신발 1벌 | 3 | 2,496 | 109.8 ms (115.7) | 114.9 ms (117.7) |
| 50벌 | 신발 1벌 | 10 | 2,496 | 136.9 ms (149.9) | 136.4 ms (282.4) |
| 50벌 | 상의 5벌 연속 (5번 합계) | 3 | 7,800 | 322.0 ms (331.5) | 334.1 ms (462.0) |

- **50벌에서 한 번 약 0.07~0.14초로, 목표(한 번 0.2초 이하) 안이다.** 최댓값 하나(282ms)가 0.2초를 넘었는데 20번 중 한 번이고 중앙값은 136ms다.
- 고정 옷이 없을 때의 5번 연속 호출은 50벌에서 합계 약 0.33초다.
- 시간은 조합 수에 비례한다(조합 하나에 약 0.04ms). 조합 수는 고정하지 않은 자리의 옷 수를 곱한 값이라, 신발을 고정했을 때(상의 × 하의 × 겉옷)가 가장 많다. `top_k`가 크면 서로 다른 추천을 고르는 단계가 조금 더 걸린다(백엔드는 선호 스타일이 있을 때 최대 10을 요청한다).
- 줄인 것: 서로 다른 추천을 고를 때 조합마다 옷 id 묶음을 매번 새로 만들던 것을 한 번만 만들게 했다(50벌·top_k 10에서 약 150ms → 137ms). 추천 결과는 그대로다.
- 대안(지금은 하지 않음): 이 PC보다 2배 넘게 느린 서버이거나 옷장이 100벌을 넘으면 0.2초를 넘을 수 있다. 그때는 자리별로 기온·장소에 맞는 상위 몇 벌만 남기고 조합하면 조합 수가 크게 준다. 추천 결과가 달라질 수 있는 변경이라 제출 전에는 넣지 않았다. 배포 서버에서 위 스크립트로 다시 잰다.

## 4. 정식 평가 방법 (팀 사진이 준비되면)

1. 평가용 사진 폴더를 만든다. 문구·기준값을 조정할 때 본 사진과 **섞지 않는다**.
2. 사진을 조건별로 고르게 넣는다: 일반 · 복잡한 배경 · 어두운 사진 · 여러 옷. 얼굴·전신이 나온 사진은 넣지 않는다.
3. 같은 폴더에 정답표 `labels.csv`를 만든다(UTF-8).

   ```
   file,category,color1,color2,condition
   knit_01.jpg,상의,베이지,,일반
   jeans_03.jpg,바지,남색,,복잡한 배경
   shirt_07.jpg,상의,하늘색,흰색,어두운 사진
   ```

   `category`는 상의·바지·스커트·겉옷·신발, 색은 `ai/ondo_ai/palette.py`의 이름, `color2`는 없으면 비운다.
4. 세 설정으로 돌려 아래 표를 채운다.

   ```bash
   cd ai
   ```

   ```bash
   ../.venv/Scripts/python scripts/evaluate.py 평가폴더 --labels 평가폴더/labels.csv
   ```

   ```bash
   ../.venv/Scripts/python scripts/evaluate.py 평가폴더 --labels 평가폴더/labels.csv --classify-on original
   ```

   ```bash
   ../.venv/Scripts/python scripts/evaluate.py 평가폴더 --labels 평가폴더/labels.csv --model fashion-clip
   ```

5. 착용 사진(옷이 여러 벌 찍힌 사진)은 정답표를 따로 만든다. 사진에 보이는 옷장 종류를 `;`로 이어 적는다. 가방·모자·원피스는 적지 않는다. 얼굴이 나오지 않게 찍은 사진만 쓴다.

   ```
   file,expected,condition
   outfit_01.jpg,"상의;바지;신발",일반
   outfit_02.jpg,"상의;겉옷;스커트;신발",복잡한 배경
   ```

   ```bash
   ../.venv/Scripts/python scripts/evaluate.py 평가폴더 --outfit-labels 평가폴더/outfit_labels.csv
   ```

   재는 것은 재현율(찾아야 할 옷 중 찾은 비율), 잘못 찾은 옷 수, 찾은 옷의 종류 정확도, 사진당 시간이다. 정답표에 옷의 위치는 없으므로 부위(상체·하체·발)별 개수로 맞춘다. 같은 부위에서 엉뚱한 것을 잡고 진짜 옷을 놓친 경우는 '찾음'으로 세어질 수 있어, 스크립트가 함께 찍는 사진별 결과를 눈으로도 확인한다. 채점 규칙은 `ai/tests/test_evaluate.py`로 고정했다.

### 평가 후 정할 것

- 분류 입력: 배경 제거 이미지(현재 기본) 대 원본
